1. INTRODUCTION                                         *redline-introduction*

redline paints whole changed lines instead of a thin gutter bar, draws the
code that was removed where it used to be, pulls the PR's review comments into
the buffer, and tracks what you have already read.

Nothing runs until you ask for it: while disabled the plugin issues no git
commands at all.

==============================================================================
2. REQUIREMENTS                                         *redline-requirements*

  - Neovim 0.10+ (uses |vim.system()| and |nvim_buf_set_extmark()| virt_lines)
  - git
  - gh, logged in            optional, only for |redline-github|
  - telescope.nvim           optional, for the fuzzy overview
  - nvim-web-devicons        optional, icons in the overview

==============================================================================
3. SETUP                                                       *redline-setup*

>lua
    require("redline").setup({
      mode      = "worktree",  -- "worktree" | "commit" | "branch"
      enabled   = false,       -- true: marks on from the moment nvim starts
      keymaps   = true,        -- false: install no default mappings
      deletions = "all",       -- "all" | "cursor" | "off"
      deleted_max = "auto",    -- longest block drawn inline, or a number, or 0
      github    = true,        -- false: never shell out to gh
    })
<
`deletions` is what opening a diff resets to, not just the initial value.
Hiding removed code through Settings is temporary: opening review resets it.

==============================================================================
4. MODES                                                       *redline-modes*

<leader>ho or :Redline asks which diff you want, then opens the overview:

  PR diff        merge-base with the default branch. The whole branch:
                 committed work and uncommitted edits together.
  Latest commit  HEAD~1. Your last commit plus anything dirty on top.
  Uncommitted    HEAD. Only what you have not committed.

The default branch comes from `git symbolic-ref refs/remotes/origin/HEAD`, so
repos on develop/trunk work without configuration. On the default branch itself
the merge-base is HEAD, so PR mode has nothing to show; redline says so once
rather than rendering an empty diff.

==============================================================================
5. MAPPINGS                                                 *redline-mappings*

Current default mappings (leader is not set by Redline):
  <leader>ho    choose review context, then overview
  <leader>ha    actions (normal / visual)
  <leader>hc    note (normal / visual, calls add_note(first, last))
  <leader>hv    viewed (normal / visual)
  ]h / [h      next / previous hunk
  <leader>h?    current help

Telescope: Enter opens; Ctrl-a / normal a closes the picker, opens the selected
file and offers actions. Normal ? opens help. Split fallback: Enter, a, ?, q.
Missing/deleted files open a read-only disk diff; file mutations are unavailable.
The context chooser names the actual detected default branch, not always main.

Use actions for staging, notes, copying, peek, refresh, undo and publishing.
Settings controls overlay, deleted code and GitHub comment visibility.
Old default shortcuts are no longer installed; Lua APIs remain available.

In either panel: <CR> jumps to the line, y copies the entry, Y copies the whole
panel, q closes.

Viewed marks identify individual changed-line occurrences, not shared text hashes.
They follow edits in an open buffer and invalidate when content changes. Saved
marks restore only with a matching file snapshot; external edits may reset them.
Legacy text-only marks are discarded. History never adds unchanged overview files.

==============================================================================
6. GITHUB COMMENTS                                            *redline-github*

Review comments are fetched automatically the first time you open a diff in a
repo: one automatic fetch attempt per repo per session, with a spinner in the
bottom-right corner. It never opens a split under you and a repo with no PR is
silent rather than an error. Settings turns them off, and on again (which
refetches rather than restoring a stale list).

Comments ride on extmarks, so they drift with your edits. A comment whose line
has since changed comes back from the API without a line number; it is kept and
marked outdated rather than dropped.

`:Redline ghsync` refetches now and opens the panel. The Lua API also takes an
explicit PR number, for reviewing a PR that is not your current branch:
>lua
    require("redline").gh_sync(412)
<
==============================================================================
7. NOTES                                                       *redline-notes*

Notes live in <repo>/.comments.txt as `path:line: text` or `path:start-end: text`.
Normal <leader>hc comments the current chunk or edits the note under the cursor;
visual <leader>hc comments selected lines. Endpoints follow edits and update on
save. Legacy notes still load. Deletion-only chunks anchor to a surviving line;
one note can exist per start line.

Concurrent instances preserve other paths' notes by re-reading disk. Simultaneous
edits to the same path remain last-writer-wins.

==============================================================================
8. COPYING                                                      *redline-copy*

Removed code is drawn with virt_lines and comments with virt_text. Neither is
buffer text, so `y` cannot reach them. Copy contextual code/comments offers what applies where
the cursor is: the removed block under it, every removed block in the file, the
comment on this line, the comments in this file, every comment on the PR, or
the notes file. With one option it copies without asking.

A single block copies as bare code, ready to paste back. A whole file gets
`@@ path:line @@` headers so you can tell where each piece came from. Text goes
to both "+ and the unnamed register.

LONG DELETIONS                                        *redline-long-deletions*

Neovim counts virt_lines as fill lines, like diff filler. <C-e> steps through
them one at a time, but `j` and <C-d> jump the whole block, so a removed block
taller than the window cannot practically be read in the buffer.

Blocks are truncated to what fits, with a footer line, and Peek removed code opens the
full block in a float. That float is an ordinary scratch buffer of real lines,
so all normal motions work, and it takes the file's filetype for syntax. `y`
copies the block, `q`, <Esc> or <CR> closes.
When several blocks cover the same line, the truncated one wins. deleted_max = 0 disables the cap.

==============================================================================
9. UNDO                                                         *redline-undo*

|u| cannot reach any of this, because none of it is buffer text. The Undo action
steps back through the redline actions that touched the git index,
.comments.txt or the viewed store: staging, unstaging, viewed ticks, notes.

Index undo snapshots `git ls-files --stage` before the change and restores it
with `git update-index`, including the "was not in the index at all" state.

==============================================================================
10. COMMANDS                                                *redline-commands*

`:Redline` chooses context then overview. Completion exposes only:
>
    open actions diff help
<
Shipped old subcommands remain hidden aliases.

:Redline diff opens a read-only scratch buffer: / searches added and removed
text, n/N moves between matches, q closes. It includes untracked files and Git's
no-final-newline markers. DISK SNAPSHOT means unsaved buffers are excluded;
the overlay uses live buffers, while overview statistics also come from disk.

Copy AI handoff confirms before copying saved notes + context + base + disk
diff. It uses the unnamed register and available clipboard, is provider-neutral,
and never executes an agent. Check for secrets before sharing.

Actions cover stage hunk/selection/file, unstage, notes, viewed, peek, refresh,
settings, undo, copying, commit staged, push, and create/open PR.
Visual staging stages only selected added/replacement lines, even in untracked
files, from the buffer without writing it. Replacements pair old/new lines by
position in fresh index hunks, retaining unselected old lines. Surplus deleted
lines stage only when the entire replacement is selected. Pure deletions cannot
be visually selected; use Stage hunk at the deletion anchor or stage the file.
Normal cursor staging stages whole hunks. All visual selections are line-based.
Commit asks for message and confirmation of staged summary, never auto-stages.
Push asks for remote, destination branch and confirmation; never force-pushes.
Create PR asks for title, body, base, draft/ready and final confirmation.
Push separately first: explicit --head prevents gh from auto-pushing.
Network operations are asynchronous argv calls, without shell interpolation.
Commit/push/PR cannot be undone by Redline. github=false disables PR actions.
==============================================================================
11. HIGHLIGHTS                                            *redline-highlights*

Shape carries add/change/delete and colour carries staged/viewed, so neither
channel has to do both jobs and the result survives colourblindness.

    RedlineAdd       ┃  added, not staged
    RedlineChange    ╏  changed, not staged
    RedlineDelete    ▁  removed here
    RedlineStaged       in the index: staged, or committed on this branch
    RedlineViewed    ✓  ticked off
    RedlineNote      󰆉  a note is attached
    RedlineGh        󰊤  a PR review comment is attached

Each also has a `…Ln` variant used for the line background, and a `…Virt`
variant for glyphs drawn inside a painted virtual line. Override them like any
other highlight group.
