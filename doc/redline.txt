*redline.txt*   Review a diff without leaving the file        Last change: 2026

==============================================================================
INTRODUCTION                                            *redline-introduction*

Redline paints changed lines, draws removed code, brings in PR review comments,
and tracks what you have read. The overlay includes unsaved buffer edits.

Requirements: Neovim 0.10+, Git. Telescope is optional for the native action
picker and fuzzy overview; nvim-web-devicons adds overview icons. Without
Telescope, actions use vim.ui.select and files use a split. GitHub features
require the logged-in gh CLI; local review works without it.
                                                       *redline-requirements*
==============================================================================
SETUP                                                         *redline-setup*
>lua
    require("redline").setup({
      mode = "worktree",     -- "worktree" | "commit" | "branch"
      enabled = false,       -- overlay off until requested
      keymaps = true,
      deletions = "all",     -- "all" | "cursor" | "off"
      deleted_max = "auto",  -- inline cap; number, or 0 for no cap
      layout = "unified",    -- "unified" | "split" (side by side)
      comments = "cursor",  -- "off" | "cursor" | "all"; PR comment bodies
      github = true,
    })
<
Opening review resets removed-code visibility to the deletions option and
the layout to the layout option.
Redline does not set your leader; keymaps=false disables default mappings.

==============================================================================
REVIEW                                                        *redline-modes*

<leader>ho or :Redline chooses context, enables the overlay, then opens files:

  Uncommitted    HEAD: uncommitted changes.
  Latest commit  HEAD~1: latest commit plus uncommitted changes. For the first
                 commit, the base is the empty tree.
  Branch / PR    Merge-base with the default branch: committed branch work
                 plus uncommitted changes.

The default branch comes from origin/HEAD, with main/master fallbacks. If the
merge-base is HEAD, branch mode shows only uncommitted work.

File overview in Telescope: Enter opens; Ctrl-a / normal a opens the selected
file then offers actions; normal ? opens help. Split: Enter, a, ?, q.
Missing/deleted files open the read-only repo disk diff, never an empty editable
file. File mutations are unavailable there. Overview diff stats come from disk.

==============================================================================
MAPPINGS                                                   *redline-mappings*

  Key            Normal mode                     Visual mode
  <leader>ho     choose context, then files
  <leader>ha     whole-file actions               selected-line actions
  <leader>hc     add/edit whole-file note         add/edit selection note
  <leader>hv     toggle viewed: file changes      selected changes
  <leader>hb     back to Changes after opening a file
  <leader>hs     side-by-side diff, or back to unified
  ]h / [h       next / previous changed location
  <leader>h?     help

Selections are line-based, even when characterwise or blockwise.
The hb and hs mappings honor keymaps=false and are added only if they do not
conflict with an existing mapping. Without it, use:
>
    :lua require('redline').back_to_review()
<

==============================================================================
ACTIONS                                                     *redline-actions*

<leader>ha opens a native Telescope picker in Normal mode. Each row shows its
[letter] shortcut: press it to run immediately. / enters fuzzy search; Enter
runs the selected row. Esc closes in either mode; normal q also closes.
/ searches actions, not the diff. Without Telescope, choose via vim.ui.select.

  s  Stage          selection, otherwise whole file
  u  Unstage        selection, otherwise whole file
  c  Comment        selection, otherwise whole file (local note)
  v  Toggle viewed  selection, otherwise whole file
  y  Copy           selection, otherwise whole file (live buffer lines)
  h  Select chunk at cursor (file)
  t  Toggle side-by-side / unified diff  see |redline-layout|

  f  Show changed files
  d  Read changes (all files)           saved-file diff
  n  Read saved notes (all files)       saved local notes
  a  Copy for AI                       selection, otherwise current file
  C  Commit staged changes (all files)  repo index, not the selection/file
  P  Push this branch
  p  Open pull request                 when GitHub enabled
  z  Undo last review action           not limited to this file/repo

Stage, Unstage, Comment, Toggle viewed, and Copy labels show "file" or
"selected lines X-Y". Local actions, copying, and undo have no confirmation step.
Comment asks for note text; empty input deletes the note at that range's start.

For a chunk: place the cursor inside it, open <leader>ha, press h, then open
Visual <leader>ha and choose an action. h only selects the review chunk's live
lines. Normal hc/hv mappings target the whole file, not the cursor chunk.

STAGING                                                     *redline-staging*

File and selection staging use the live buffer without saving it, including
untracked files. Selected staging includes only selected added/replacement
lines. Replacements pair old/new lines by position in fresh index hunks;
unselected old lines remain. Surplus deleted lines stage only when the entire
replacement's new side is selected.

Whole-file staging applies Git's path-specific clean conversion, including
.gitattributes filters/LFS, and records executable-bit changes when core.fileMode
is enabled. Both scopes refuse ignored untracked files. Partial staging refuses
filtered/encoded files or patches requiring clean conversion; use whole-file
staging instead. Neither scope saves the buffer.

Selected unstage maps live lines to the index. A selection overlapping an
unstaged replacement is ambiguous: the action is refused without changing the
index; use whole-file unstage. Newly inserted unstaged lines have no index
counterpart. Unstage leaves the buffer and disk unchanged.

Pure deletions are virtual text, not selectable buffer lines. h cannot select
them; selected stage/unstage cannot target them. Use normal <leader>ha then s/u
for the whole existing file. Entirely missing/deleted files are read-only in
this workflow; handle their index changes with Git outside the action menu.

PUBLISHING                                               *redline-publishing*

C shows the repo staged summary and asks only for a commit message. It commits
the entire repo index, never auto-stages, and adds no confirmation dialog.

P pushes HEAD only to the same branch name. If the current branch tracks a
different name (for example, topic tracks origin/main), it refuses to push;
configure a matching upstream with Git first. Remote selection honors
branch.<name>.pushRemote, then remote.pushDefault, then branch.<name>.remote.
Without that configuration, it uses the sole remote or asks which remote if
several exist. No destination or confirmation prompt; never force-pushes.

The single p action opens an existing PR in the foreground browser, or opens
GitHub's creation form if no PR exists. Finish creation in the browser; there
are no local title/body/confirmation prompts. Lookup/auth/network errors are
reported, not treated as a missing PR. It never pushes automatically: use P
separately when needed. Redline cannot undo commit, push, or PR operations.

Side by side                                                 *redline-layout*

The overlay is unified by default: removed code is drawn inline, above the
lines that replaced it. <leader>hs (or action t, or :Redline layout) switches
to side by side: the base version opens read-only in a window on the left and
Vim's diff mode lines the two up, while the right side keeps Redline's staged,
viewed, and note marks on the live buffer, unsaved edits included. Inline
removed code is hidden while it is on. The left window follows whichever file
you open in the right one, and each tab gets its own pair.

Press <leader>hs again, or close the left window, to return to unified.
Opening a review resets the layout to the layout option. :Redline split and
:Redline unified set it directly.

==============================================================================
NOTES AND VIEWED                                             *redline-notes*

Notes live in <repo>/.comments.txt as path:line: text or path:start-end: text.
Normal <leader>hc targets the whole file; visual hc targets selected lines.
Endpoints follow edits and update on save. One note can exist per start line.
Concurrent instances preserve other paths' notes; simultaneous edits to the
same path are last-writer-wins.

Viewed marks track individual changed-line occurrences, follow edits, and
invalidate when content changes. Saved marks restore only for a matching file
snapshot; external changes may require reviewing again.

GITHUB COMMENTS                                             *redline-github*

PR review comments fetch in the background, with one automatic attempt per
repo per session. No PR is silent; outdated comments are retained. github=false
disables GitHub features, including action p.

==============================================================================
DIFF AND COPYING                                              *redline-copy*
                                                      *redline-long-deletions*
:Redline diff or d (Read changes (all files)) opens Changes in a read-only,
full-screen tab. It compares saved files with the review base, includes
untracked files and no-final-newline markers, and leaves out .comments.txt and
unsaved edits. Use it to read long deletions cut short in the overlay.

  /          Search text; n/N move between matches.
  ]h / [h    Next / previous diff hunk.
  Enter      Map the saved diff line to its live source position. If that line
             changed or was deleted, use a nearby surviving line and warn
             "Approximate location". Binary or encoded text also warns when
             mapping is unsafe. Missing or deleted files stay in the diff.
  ?          Open Help.
  q / Esc    Back: close Changes or Help and return to where you opened it.

Changes and Help each use a full-screen tab and preserve your existing splits.
Changes stays open when Enter takes you to a source file. Use <leader>hb to
return directly, then q/Esc for Back. It prefers the last review used from that
source window, then the most recently visited open review. gt/gT still cycle
through tabs.

Action y (Copy) copies live buffer lines only, not removed text or comments.
Action a (Copy for AI) copies changes from the review base to the live buffer,
plus local notes and currently loaded PR review comments. It covers only the
selected lines or the current file, never the whole repo. A selection also
includes its live code; whole-file copy leaves out unchanged code.

Copy for AI reads fresh saved notes, including external edits, and uses their
tracked live positions when available. It does not save code or write notes.
Selection copy includes overlapping notes and PR comments that can be matched
to those lines, and reports any omitted because their positions are uncertain.
Whole-file copy includes them, with saved or unavailable positions marked.
Both copy actions use the unnamed register and try the clipboard, without
confirmation. Copy for AI does not run an agent or send anything automatically.
Check for secrets before sharing.

UNDO                                                          *redline-undo*

Action z undoes the session's last index, note, or viewed change, even from
another file/repo, without confirmation. Normal Vim u only undoes buffer edits.
Publishing is not part of Redline undo.

==============================================================================
COMMANDS                                                  *redline-commands*

:Redline equals :Redline open. Completion exposes only:
>
    open actions diff layout help
<
Historical subcommands and Lua APIs remain available for existing configurations;
their no-argument scopes may differ from the default mappings.

HIGHLIGHTS                                              *redline-highlights*

RedlineAdd, RedlineChange, RedlineDelete, RedlineStaged, RedlineViewed,
RedlineNote, RedlineGh. Each has Ln background and Virt virtual-line variants.
Override them like normal highlight groups.
